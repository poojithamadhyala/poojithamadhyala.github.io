⚡ How It Works

You ask: "What is the default MuJoCo timestep?"

→ Agent reads question
→ Calls search_docs tool → Vector Store (cosine similarity)
→ Gets top-k matching chunks ← relevant passages returned
→ Reasons over evidence
→ Returns structured JSON:

{
  "answer": "0.002 seconds (500 Hz)",
  "citations": [{"doc_id": "mujoco_basics", "chunk_id": "a3f2b1"}],
  "confidence": "high"
}

✨ What Makes This Different

🔄 Agentic Loop

Multi-turn tool-use loop: the LLM plans, calls tools, evaluates results, and can search again — not a one-shot pipeline. Hard budget of 6 tool calls controls cost.

✅ Validated Output

Every response is parsed into a Pydantic schema with answer, citations, confidence, and tools_used. Malformed LLM output is caught, never propagated.

📊 Eval Framework

8 labeled eval cases with Hit@k and MRR scoring. CI threshold gate (Hit@4 < 0.8 = failure) catches retrieval regressions before they ship.

🧪 Mocked Tests

Dependency-injected LLM client — 5 unit tests run the full tool-calling path without API keys, in under a second. Zero flaky external calls in CI.
